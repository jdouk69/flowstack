# Flowstack on Sites

Standalone migration of jdouk69/flowstack. Hosted privately using ChatGPT sign-in.

Implemented: original Home, saved Workflows wizard, History, theme Settings; owner-scoped persistent workflow records; PDF uploads and downloads in private R2; SHA-256 duplicate checks within each workflow; merging 2–20 selected PDFs in selection order; history of uploads and merges. PDF uploads are limited to 10 MB each, merges to 20 MB of inputs.

Personal Google authorization and read-only Gmail workflow search are connected. Manual Run workflow now collects attachments in resumable batches, preserves originals in R2, binds the intended Drive folder and saves verified Drive copies. Drive folder browsing/sorting is restored. Existing original PDFs in the bound workflow folder can be imported into R2. Drive merge supports all eligible originals in name order or selected PDFs in click order; preserves individual sources and stores the merged output locally and on Drive. Repeated identical merges reuse the prior output. Live Google collection/Drive-write acceptance is pending. Manual files save in Sites storage, not Drive. Current verified comparison and the gate before additional audit work are in `BASE44_PARITY.md`. Original Base44 server code is retained under migration-reference and is not executed. No original Base44 data is imported or synced.

Run dependency setup/build with the Sites helpers. Schema migrations are generated by `npm run db:generate`. Local backend checks use ephemeral Miniflare resources; no live user records are changed.

This project is separate from the user's Base44 repository. Publishing it does not update the Base44 app.

Baseline additions: Dashboard Run all workflows executes saved collection jobs serially. Documents → Copy to Drive exports uploads or local merges to a selected workflow folder without changing original workflow/source/audit records. Idempotent export retries and source-preservation fixtures pass; live phone/Drive acceptance remains separate. Customer download links and larger-file limits are tracked in BUILD_STATUS.md.
